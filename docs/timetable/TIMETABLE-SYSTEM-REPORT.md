# تقرير نظام الجدول الدراسي — الشرح الكامل، المطابقة مع مواصفة Master Timetable، النواقص والمقترحات

**التاريخ:** 2026-10-08 · **الفرع:** V2 · **الأساس:** فحص مباشر للكود (آخر commit `7d0ce35`) + وثائق `docs/timetable/*`.

## 1. الصورة العامة
الجدول ليس شاشة فقط؛ هو **سياق (Bounded Context) كامل** باسم `Timetable` مبني بالمعمارية النظيفة:

| الطبقة | المسار | المحتوى |
|---|---|---|
| Domain | `app/Domain/Timetable/` | `TimetableBoard` (نموذج الجدول في الذاكرة)، المحلّل `TimetableAdvisor`، المدقق `TimetableAuditor`، `TimetableQualityScorer`، `TeacherWorkloadAnalyzer`، `SubstituteRanker`، `GroupSplitPlanner`، `TimetableVersionComparer`، `TimetableFingerprint`، المحرك `Solver/HeuristicTimetableSolver` (1248 سطر) خلف `TimetableSolverInterface`، `ConstraintCompiler`، `ConstraintRuleCatalogue` |
| Application | `app/Application/Timetable/` | ~35 Command/Handler و~12 Query (توليد، تطبيق، نشر، اعتماد، تثبيت، أنشطة، قيود، إتاحة...) |
| Infrastructure | `app/Infrastructure/Persistence/Timetable/*`، `Jobs/ExecuteTimetableGenerationJob.php` | مستودعات Eloquent، مهمة الطابور للتوليد |
| HTTP | `TimetablePageController`, `TimetableEngineController`, `Api/TimetableEngineApiController` + FormRequests | متحكمات رقيقة |
| UI | `resources/js/pages/timetable/{index,student,show}.tsx`، `components/timetable/engine/*`، `components/timetable/master-timetable.tsx` (غير مُرسَل بعد) | الواجهة |
| Schema | مخطط `timetable` في PostgreSQL | 13 جدولاً (أدناه) |

## 2. من أين يأخذ الجدول بياناته (لا يكرر أي كيان)
الجدول **لا يُدخل** مدرسة أو فرعاً أو معلماً أو مادة من جديد؛ يقرأها من مالكيها (Source of Truth):

| الكيان | المصدر | كيف يستخدمه الجدول |
|---|---|---|
| المدرسة | `organization.schools` | كل صف في الجدول يحمل `school_id` + RLS على `app.current_school_id`؛ المسار محمي بـ `require.school.context` |
| السنة الدراسية / الفصول / العطل | `academic.academic_years`, `terms`, `holidays` | كل شيء مقيد بـ `academic_year_id`؛ فلتر السنة في الشريط؛ النشاط يمكن ربطه بـ `term_id` |
| الفرع ← القسم ← الاختصاص | `organization.branches`, `organization.departments`, `vocational.specializations` | فلاتر الشريط؛ تجميع «عرض الكل» حسب «الفرع › الاختصاص»؛ نطاقات القيود (branch/department) |
| المرحلة / الصف / الشعبة | `academic.grade_levels`, `enrollment.classes`, `enrollment.sections` | **الشعبة هي وحدة الصف في الجدول** (= class في aSc). رمز الشعبة A/B/C من SSOT |
| الطلاب | `enrollment.enrollments` (النشطة) | عدد الطلاب لكل شعبة (للسعة وتقسيم المجموعات)؛ جدول الطالب يُشتق من شعبته ومجموعاته — الطالب لا يدخل المحرك |
| المواد | `curriculum.subjects` (`subject_type=3` = عملي) | المادة العملية تُوضع حصصاً مزدوجة |
| النصاب الأسبوعي | `curriculum.curriculum_subjects.weekly_hours` (منهج القسم ثم العام) | عدد حصص المادة في الأسبوع |
| المعلمون والإسناد | `teachers.teaching_assignments`, `teacher_subjects`, `teacher_qualifications` | «المتطلب» = شعبة × مادة × معلم × نصاب؛ لا يُسمح بمعلم غير مؤهل للمادة |
| القاعات | `organization.rooms` (`capacity`, `room_type`) | عرض حسب القاعة، متطلب نوع القاعة، فحص السعة |
| الورش والمعدات | `vocational.workshops` (`capacity`, `safety_capacity`), `workshop_equipment` | الورشة مورد حصري بسعة أمان؛ المعدات **غير مستخدمة بعد** |
| المتطلبات السابقة | `curriculum.prerequisites` | أساس قاعدة «النظري قبل العملي» |
| الحضور | `attendance.sessions.period_id` → `timetable.periods` | الحضور يقرأ الحصص؛ يوجد API للجدول الفعّال لتاريخ |

**سلسلة البيانات:** المدرسة → السنة → الفرع → القسم/الاختصاص → الصف → الشعبة → المنهج (نصاب المادة) → إسناد المعلم → **المتطلب/النشاط** → الخانة (يوم × حصة × أسبوع) → القاعة/الورشة → الإصدار المنشور.

## 3. جداول قاعدة البيانات الخاصة بالجدول (مخطط `timetable`)
كلها: `school_id NOT NULL` + FORCE RLS + trigger يرفض الحذف (لا حذف نهائي) + `effective_from/to` حيث يلزم.

| الجدول | الغرض |
|---|---|
| `periods` | الحصص والاستراحات لليوم الدراسي (رقم، بداية، نهاية، نوع: حصة/استراحة) |
| `schedules` | **شبكة العمل**: شعبة × يوم × حصة، معلم، معلم مشارك، قاعة، مجموعة، أسبوع، `locked_at`، `joined_to_schedule_id`، `activity_id`. فهارس unique جزئية تمنع ازدواج المعلم/الشعبة/القاعة/المعلم المشارك |
| `schedule_exceptions` | تغييرات بتاريخ (بديل معلم/قاعة ليوم) |
| `configs` | إعدادات المدرسة/السنة: أيام العمل، عدد أسابيع الدورة، حدود يومية، مدة التبديل للحصة المزدوجة، policy |
| `activities` | النشاط: مادة، نوع (17 نوعاً)، عدد أسبوعي، طول الكتلة، التوزيع (مثل 2+2+1) ثابت/مرن، قاعة/نوع قاعة/ورشة، نمط الأسابيع، الفصل |
| `activity_sections` | أهداف النشاط (عدة شعب = صفوف مدموجة، أو مجموعة من شعبة) |
| `activity_teachers` | معلم رئيسي/مشارك/مساعد + `sessions` (مثال: 5 حصص والمعلم B في 3 منها) |
| `divisions` / `division_groups` / `group_members` | تقسيم الشعبة إلى مجموعات وأعضاء كل مجموعة |
| `availability` | عدم إتاحة/تفضيل/تجنّب لمعلم أو قاعة أو شعبة أو ورشة (FK صريح لواحد فقط) |
| `constraint_rules` | القيود: نوع، أولوية، نطاق بأعمدة FK صريحة، params JSONB، سبب، تواريخ |
| `versions` / `version_entries` | الإصدارات (لقطة كاملة غير قابلة للتعديل)، حالة، أب، بصمة المصدر، الجودة، الاعتماد والنشر |
| `generation_runs` | عمليات التوليد: نمط، نطاق، حالة، تقدم، لقطة الإدخال، النتيجة، مفتاح idempotency، **عملية واحدة نشطة لكل مدرسة/سنة** |

## 4. كيف يُنشأ الجدول — خطوة بخطوة (سير العمل الفعلي)
1. **اختيار السنة** من فلتر الشريط (المدرسة من سياق المدرسة الحالي).
2. **«توقيت الحصص»** (شريط «إضافة» › الإعداد): تعريف الحصص والاستراحات، أو «توزيع الاستراحات تلقائياً» من بداية اليوم ومدة الحصة. **بدون حصص لا يعمل شيء** (المحلل يعطي `no_lesson_periods`).
3. **المتطلبات المسبقة خارج الشاشة:** منهج بنصاب أسبوعي، وإسناد تدريس (صفحة المعلمين) لكل شعبة/مادة، والمعلم مؤهل للمادة (`teacher_subjects`). إن لم يوجد إسناد تظهر رسالة «لا توجد مواد مسندة لهذه الشعبة — أسند التدريس من صفحة المعلمين».
4. **«إعدادات الجدول»**: أيام العمل (الافتراضي الأحد–الخميس)، أسابيع الدورة (أسبوع/A-B/n)، حد المعلم اليومي (الافتراضي 6)، حد المادة اليومي (2)، مدة التبديل للمزدوجة (≤10 دقائق).
5. **«الأنشطة والمجموعات»** (اختياري لكن مطلوب للحالات المتقدمة): «إنشاء من المنهج» يقترح الأنشطة، ثم تعديل النوع/العدد/الكتلة/التوزيع/القاعة/الورشة/الأسبوع، صفوف مدموجة، معلم مشارك، «تقسيم الشعبة» إلى مجموعات (حسب العدد أو سعة الورشة، مثل 36 → 18+18). **بدون أنشطة يعمل النظام بالمتطلبات المشتقة** (حصص مفردة، العملي مزدوج).
6. **«الإتاحة»**: شبكة أيام × حصص لمعلم/قاعة/شعبة/ورشة؛ النقر يدور بين: متاح ← غير متاح ← تجنّب ← مفضّل.
7. **«القيود»**: إضافة قواعد بأولوية ونطاق «ينطبق على» (18 نوعاً — القسم 7).
8. **«الجاهزية والجودة»**: حكم READY/BLOCKED + نسبة الجاهزية + المعوقات + عبء المعلمين.
9. **التوليد**: إما «توزيع تلقائي» سريع لشعبة واحدة (متزامن)، أو **«توليد الجدول»** للمدرسة/نطاق (في الطابور) ← مراجعة النتيجة ← «اعتماد في الجدول» أو «تجاهل» أو «حفظ كإصدار».
10. **التعديل اليدوي**: سحب وإفلات، استبدال، زحف، تثبيت، «اقتراح أماكن».
11. **«تدقيق الجدول»**: أخطاء/تحذيرات/معلومات مع «انتقال» للخانة.
12. **«الإصدارات والنشر»**: لقطة ← إرسال للاعتماد ← اعتماد/رفض (عبر workflow) ← نشر من تاريخ ← يصبح الجدول الفعّال؛ السابق يصبح «مستبدَل» ويبقى في السجل.
13. **التشغيل**: «بديل ليوم» لغياب معلم، API الجدول الفعّال لتاريخ (للحضور)، جدول الطالب، تصدير CSV، طباعة A3.

## 7. المحرك (Solver) والقيود
- **المسار:** Controller ← `QueueTimetableGeneration` (idempotency + عملية واحدة نشطة) ← `ExecuteTimetableGenerationJob` (يعيد ربط سياق المدرسة) ← `TimetableBoardLoader` (لقطة + بصمة) ← `GenerationGate` (يرفض إن وُجد معوق إلا في النمط المرن) ← `ConstraintCompiler` ← `HeuristicTimetableSolver` ← التدقيق والتقييم ← حفظ في `generation_runs` (لا يُطبق تلقائياً) ← `ApplyTimetableGeneration` (يرفض إن تغيّرت البيانات منذ اللقطة).
- **الخوارزمية:** الحصص المثبتة أولاً ← البناء: الكتلة الأصعب أولاً في الموضع الأقل عقوبة ← عند التعثر: سلسلة إزاحة (ejection) بعمق 2 ← تحسين بـ simulated annealing بـ seed (حتمي) ← تشخيص لكل كتلة غير موضوعة: لماذا رُفض كل موضع + العائق الوحيد.
- **الأولويات:** CRITICAL 1,000,000 · VERY_HIGH 100,000 · HIGH 10,000 · MEDIUM 1,000 · LOW 100 · VERY_LOW 10. النمط يحدد أين يبدأ «الصلب»: صارم ≥ HIGH، متوازن ≥ VERY_HIGH، مرن = CRITICAL فقط.
- **القواعد الثابتة (دائماً):** لا ازدواج للمعلم/المشارك/الشعبة/القاعة/الورشة، توافق مجموعات التقسيم الواحد، عدم الإتاحة، سعة القاعة/الورشة، تتابع الكتلة، توزيع كتل النشاط.
- **كتالوج القواعد (18):** `teacher_max_per_day`, `teacher_min_per_day`, `teacher_max_gaps_per_day`, `teacher_max_consecutive`, `teacher_max_days`, `section_max_per_day`, `section_min_per_day`, `section_no_gaps`, `section_end_by`, `subject_max_per_day`, `subject_not_consecutive_days`, `forbidden_slots`, `preferred_slots`, `activity_before`, `activity_same_day`, `activity_not_same_day`, `activity_not_same_time`, `teachers_not_simultaneous`.
- **الأسبقية:** فرع < قسم < مرحلة < صف < شعبة < مادة < معلم/قاعة < نشاط (الأكثر تحديداً يفوز، ويُسجل مصدر كل قيد).

## 8. دورة الحياة والأمان
- **حالات الإصدار:** مسودة ← مراجعة ← معتمد/مرفوض ← منشور ← مستبدَل؛ والأرشفة. «نشط» = المنشور الذي يشمل اليوم.
- **الصلاحيات:** `timetable.view`, `schedule.create/update/cancel`, `exception.create/update`, `constraints.manage`, `generate`, `approve`, `publish` + دور `timetable_approver`.
- **الحماية:** RLS على كل الجداول، رفض DELETE، `version_entries` غير قابلة للتعديل، أحداث `TimetableEngineChanged` في Outbox داخل نفس المعاملة، idempotency للتوليد والنشر، بصمة المصدر لكشف «الجدول قديم».
- **الاختبارات:** وحدات (Solver 26، Engine 21، Analysis 15، Builder 12، PeriodTimeGuard 12، SchoolDayPlanner 5) + PostgreSQL (Builder 13، Engine 14) تشمل سيناريو §147 المهني كاملاً.

## 10. مقترحات التحسين والتكامل (بالأولوية)
**أ. تكامل مع وحدات أخرى (الأعلى قيمة)**
1. **الحضور ← الجدول الفعّال:** التأكد أن جلسات الحضور تُبنى من `GetEffectiveTimetable` (معلم/مادة/قاعة/مجموعة) بدل الإدخال اليدوي.
2. **صفحة المعلمين ← العبء:** إظهار عبء الجدول (`TeacherWorkloadAnalyzer`) في ملف المعلم، وتحذير عند إسناد يتجاوز السعة.
3. **المنهج/الإسناد/التسجيل ← تحذير القِدم:** عرض «الجدول المنشور قد تأثر» في صفحات المصدر أيضاً، لا في الجدول فقط.
4. **التسجيل ← المجموعات:** ملء `group_members` تلقائياً عند التقسيم ونقل الطالب بين الشعب.
5. **الإشعارات:** مستهلك لأحداث `TimetableEngineChanged` (نُشر/اكتمل التوليد/فشل/تغيّر).
6. **الامتحانات:** حجز خانات بنوع `ExamSlot` فقط بطلب من سياق الامتحانات، دون ربط بـ `exam_sessions`.

**ب. الواجهة (ضمن نفس التصميم والمكونات)**
7. لوحة تعارض جانبية بأزرار إصلاح + إضافة `suggested_fixes` للمدقق، وتوسيع المدقق للقاعات والسعة والتسلسل.
8. تغيير القاعة/المجموعة من «تعديل الحصة» + قائمة سياق للبطاقة.
9. Undo/Redo مسجل + اختصارات (Ctrl+Z/Y، L للتثبيت، Ctrl+F للبحث).
10. عرض المادة + ملخص الفرع/الاختصاص + أنماط البطاقة الثلاثة.

**ج. المحرك والبيانات (تحتاج migrations → بوابة database-change وموافقة)**
11. أنواع القيود الناقصة (تزامن، تتابع، قبل بدرجات، القاعة نفسها، المجموعات تنتهي معاً).
12. Bell sets وأنواع الاستراحات (بدون تغيير PK SMALLINT للحصص).
13. وحدات المعدات لكل خانة، وقوالب القيود كبيانات.
14. التغييرات المؤقتة (نقل/إلغاء/حدث بتاريخ) كامتداد لـ `schedule_exceptions`.
15. المواد الاختيارية واختيارات الطلاب.
16. أقل مجموعة تخفيف (deletion filter) للتشخيص.

**د. التقارير:** PDF/Excel، طباعة معلم/قاعة/طالب، تقارير استخدام القاعات والورش والجودة.
